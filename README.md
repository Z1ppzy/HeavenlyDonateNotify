# HeavenlyDonateNotify

Предупреждает игроков об окончании временной привилегии **Sponsor** по данным LuckPerms
на прокси **Velocity**. Ставится только на Velocity; на игровые серверы ничего ставить не нужно.
Плагин только читает LuckPerms API: таблицы базы не трогает, группы, права и сроки не меняет,
ничего не выдаёт игрокам автоматически.

## Что видит игрок

```text
Срок вашего Sponsor истечёт через 23 часа 59 минут.
Окончание: 15 ноября в 18:30 МСК.
После окончания у вас останется Premium.
[Продлить Sponsor]
```

Кнопка открывает адрес магазина из `shop.url`; пока адрес не задан, строка с кнопкой скрыта.
Остаток показывается двумя старшими единицами («2 дня 5 часов», «45 минут»), без «0 дней».
Дата — в часовом поясе `time.zone` (по умолчанию `Europe/Moscow`), с годом, если окончание в другом году.

## Поведение

- Отслеживается собственное членство в группе `sponsor` и в группах, которые её наследуют.
  Бессрочное назначение делает Sponsor бессрочным — уведомлений нет. Среди временных берётся
  самый поздний срок. Назначения с контекстами, которые прокси не выполняет (например,
  `server=survival`), пропускаются с записью в журнале; если такое назначение бессрочное,
  статус игрока считается неопределённым и ничего не отправляется.
- Пороги по умолчанию: за 3 дня, 1 день, 3 часа и 30 минут. Если игрок пропустил несколько порогов,
  уходит только самый близкий к окончанию. Каждый порог — один раз на конкретный срок.
- Проверка выполняется через `checks.login-delay` после первого подключения к игровому серверу,
  раз в `checks.interval` для игроков онлайн и после пересчёта прав в LuckPerms (продление,
  снятие, синхронизация из общей базы). Переходы между режимами новых проверок не создают.
- Перед отправкой данные читаются заново: после продления или снятия группы устаревшее
  уведомление не уходит; продление начинает отслеживание нового срока с нуля.
- Срок истёк во время отсутствия игрока — при следующем входе одно сообщение об окончании,
  и только если плагин видел этот срок раньше. Снятие группы до срока сообщение не создаёт.
  Недоступность LuckPerms или хранилища — ничего не отправляется и ничего не угадывается.
- «После окончания у вас останется Premium» — только при независимом бессрочном Premium
  (напрямую или через другую бессрочную группу, не через `sponsor → premium`).
  Если остаются только группы из `groups.ordinary` — «станете обычным игроком»;
  персонал, временные группы или неясные данные — нейтральный текст.

### Вход и лимбо

Velocity видит игрока ещё в лимбо LimboAuth (пароль, второй фактор AuthVelocityPlugin), где
`getCurrentServer()` пуст. Сообщения уходят только игроку на игровом сервере **и** только пока
LimboAuth загружен и готов: плагин зовёт его публичный `isAuthReady()` отражением, как это делает
AuthVelocityPlugin. Без готового LimboAuth Velocity пустил бы игроков без пароля, поэтому
подключение к серверу само по себе входом не считается. Для сети без LimboAuth —
`checks.require-limboauth: false`.

### Защита от повторов

История хранится в `plugins/heavenlydonatenotify/history.db` (SQLite, WAL). Уведомление
привязано к UUID, группе, сроку окончания и порогу; запись делается атомарно до отправки,
поэтому перезапуск прокси, повторный вход, переход между серверами и параллельные проверки
не дают дубликатов. Если игрок вышел до доставки, запись снимается и предупреждение придёт позже.
При ошибке хранилища отправка приостанавливается (ошибка в журнале не чаще раза в 5 минут).
Записи старше `history.retention` удаляются при старте и раз в сутки.

Предполагается один Velocity. Если прокси несколько, у каждого будет своя история и игрок может
получить предупреждение с каждого: нужна общая история (одна база вместо локального SQLite).

## Команды и права

| Команда | Что делает | Право |
|---|---|---|
| `/donatenotify reload` | Перечитать `config.yml`; при ошибке действует прежний конфиг, причина в ответе и журнале | `heavenlydonatenotify.reload` |
| `/donatenotify status <игрок>` | Назначения LuckPerms, срок, остающийся статус, отслеживаемые сроки, отправленные уведомления, состояние входа и плагина | `heavenlydonatenotify.status` |
| `/donatenotify preview <игрок> <порог>` | Показать администратору сообщение для порога (`3d`, `1d`, `3h`, `30m`, `expired`); игроку не отправляется, история не меняется | `heavenlydonatenotify.preview` |

Псевдоним — `/dnotify`. Игрок офлайн ищется в LuckPerms по нику. Выдача прав, например:

```text
lpv group admin permission set heavenlydonatenotify.status true
```

Перезагрузка Velocity (`/velocity reload`) тоже перечитывает конфиг.

## Конфигурация

Файл `plugins/heavenlydonatenotify/config.yml` создаётся при первом запуске
(образец — [src/main/resources/config.yml](src/main/resources/config.yml)).
Отсутствующие ключи берутся из образца.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `groups.sponsor`, `groups.premium`, `groups.ordinary` | `sponsor`, `premium`, `[default]` | Группы LuckPerms |
| `thresholds` | `[3d, 1d, 3h, 30m]` | Пороги предупреждений (`d`, `h`, `m`, `s`) |
| `checks.login-delay`, `checks.interval` | `10s`, `60s` | Задержка после входа и период проверки онлайн |
| `checks.require-limboauth` | `true` | Отправлять только при готовом LimboAuth |
| `history.retention` | `90d` | Срок хранения истории |
| `time.zone`, `time.zone-label`, `time.date-format`, `time.date-format-other-year` | `Europe/Moscow`, `МСК`, … | Дата окончания |
| `shop.url` | пусто | Адрес магазина; пусто — кнопка скрыта |
| `messages.*` | см. образец | MiniMessage-шаблоны, тексты об остающемся статусе, кнопка |

Плейсхолдеры шаблонов: `<player>`, `<privilege>`, `<remaining>`, `<end_date>`,
`<remaining_status>`, `<renew_button>`, `<shop_url>`. Строка, ставшая пустой после подстановки,
не выводится. Неверные значения (порог вне диапазона, неизвестный пояс, не-http адрес, опечатка
в теге MiniMessage) отвергаются с указанием ключа; при старте с битым конфигом действуют
встроенные значения, об ошибке сообщает журнал и `/donatenotify status`.

## Сборка и установка

Сборка: JDK 25, `./gradlew build` (тесты входят). Единственный устанавливаемый файл —
`build/libs/HeavenlyDonateNotify.jar`. Собирается под Velocity API 4.2.0 и LuckPerms API 5.4;
рабочий прокси — Velocity 4.2.x на Java 25.

1. Положить `HeavenlyDonateNotify.jar` в `plugins/` прокси Velocity. LuckPerms на прокси обязателен
   (плагин без него не загрузится); LimboAuth — необязательная зависимость, но по умолчанию
   без него уведомления не отправляются.
2. Запустить прокси: появится `plugins/heavenlydonatenotify/config.yml`. Указать `shop.url`,
   при необходимости тексты и пороги, выполнить `/donatenotify reload`.
3. Выдать права командам (см. выше). В журнале должна появиться строка `event=donate_notify_ready`.

На игровые серверы ничего не устанавливается и их конфигурация не меняется.

## Проверка синхронизации LuckPerms

Плагин читает LuckPerms прокси, поэтому прокси должен видеть изменения, сделанные на игровых
серверах или сайтом.

1. На прокси `lpv info`, на любом игровом сервере `lp info`: одинаковые `Storage Method`
   и настроенный `Messaging Service` (sql, redis или pluginmsg).
2. На игровом сервере выдать тестовому аккаунту временный Sponsor:
   `lp user <ник> parent addtemp sponsor 2h`.
3. На прокси в течение нескольких секунд `lpv user <ник> info` должен показать назначение
   со сроком. Если нет — `lpv sync` и проверить `messaging-service` в конфиге LuckPerms прокси.
4. `/donatenotify status <ник>`: назначение, «Sponsor: временный · окончание …», остающийся
   статус. `/donatenotify preview <ник> 3h` покажет текст сообщения.
5. Снять группу `lp user <ник> parent remove sponsor` — статус покажет
   «снят вручную до срока», сообщение об окончании не уйдёт.

## Что проверено и что требует работающей сети

Проверено локально (`./gradlew build`, JDK 25, 64 тестов JUnit 5 на управляемых часах):
пороги и их границы, пропущенные пороги, вход после пропусков, продление, бессрочный Sponsor
(напрямую и через наследование), независимый Premium против `sponsor → premium`, персонал,
истечение офлайн, ручное снятие, повторная покупка, перезапуск (повторное открытие SQLite),
параллельные проверки в одном процессе и через два соединения, отказ хранилища,
недоставленное сообщение, неоднозначные назначения, рендер MiniMessage и кнопка, форматы дат
и остатка, валидация и перезагрузка конфига, хранилище SQLite, решение гейта входа.

Требуют работающей сети и не проверялись здесь: реальная задержка синхронизации LuckPerms между
серверами и прокси, доставка `UserDataRecalculateEvent` после удалённых изменений, вызов
`isAuthReady()` у установленной сборки LimboAuth, отображение цветов и кнопки в клиенте,
поведение UUID лицензионных игроков после лимбо (плагин берёт данные по UUID игрока на игровом
сервере и при необходимости загружает их из общей базы).

## Ограничения

- Снятие группы вручную, пока игрок офлайн, обнаруженное уже после даты окончания, неотличимо
  от истечения: уйдёт сообщение об окончании (доступа в этот момент действительно нет).
- Контекстные назначения (`server=…`, `world=…`) на прокси не оцениваются: временные пропускаются
  с записью в журнале, бессрочный контекстный Sponsor переводит игрока в состояние
  «не определён», и ему ничего не отправляется.
- Сообщение уходит в чат; игрок в лимбо авторизации его не получит и будет проверен после входа
  на игровой сервер.
